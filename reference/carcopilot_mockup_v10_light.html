CAR·COPILOT — Light theme reference

Apple HIG-influenced light palette with indigo as the single primary action color. Every semantic color gets two variants — a Fill for backgrounds and an Inline for body text — because on a white surface, a yellow #F5B800 button is fine but yellow body text is invisible. The discipline below is the contract.

No amber. The matrix has three rows because the system has three semantic colors — indigo carries primary action AND inline emphasis; red marks severe; green marks healthy. The "in progress" status pill that historically read as warning amber is now indigo-soft + indigo-inline, because there is no surface where a fourth hue earns its keep on this palette.

Brand identity — single-hue cohesion

  • The brand mark uses indigo-inline (#4F46E5), not a separate brand color. Earlier drafts kept a single amber decorative dot as "brand warmth," but on the indigo+red+green+neutral palette the warm note read as off-key — the dot felt like a leftover, not a deliberate accent. The current direction threads the indigo identity through every CAR·COPILOT element: brand-mark dots (Splash, TopBar, MechanicDraft "FROM CAR · COPILOT"), the brand underline, the AI strip heading.
  • Two indigos, one identity. Buttons and severity bars use the indigo Fill (#6366F1); brand marks, inline emphasis, and small chrome use the slightly deeper Inline (#4F46E5). The pair reads as one family of "this product's voice," with the small tonal step distinguishing "tap here" from "you are here."
  • No amber, no fourth hue. Earlier passes kept an amber "warning" tier alongside indigo/red/green. On-device review showed the residual amber (used for inline emphasis and the in-progress pill) read as off-key brownish-yellow on white. Collapsing it into the primary indigo simplified the system without losing any signal — the in-progress pill is still distinct from the resolved (green) and recurrence (red) variants.

Implementation notes for future agents

  • Single SOT: tokens above are mirrored in app/src/main/java/com/example/carcopilot/ui/theme/Color.kt. Change tokens there; do not patch composables one-by-one.
  • Two-tone rule: for any color with a Fill and an Inline variant, Fill is for backgrounds (buttons, bars, dots), Inline is for body text on white. The Severity → Color helpers in ThinkingDots.kt expose both as accentColor() (fill) and accentInlineColor() (text).
  • Soft pills: status pills always render as Soft background + Inline text. Never solid-fill pills.
  • Hairline + barely-there shadow: cards use a 1px border at rgba(0,0,0,0.08) plus an optional 0 1px 2px rgba(0,0,0,0.03) shadow. Avoid Material elevation past 1dp.
  • Mono is technical: JetBrains Mono is reserved for DTC codes, readings, debug labels. Geist carries body and chrome. Don't broaden mono usage.
  • One primary action color: every "this is the thing to tap" affordance uses indigo Fill. Severity-tinted CTAs only for severe/healthy cases.
  • Pure black is banned: use #1D1D1F for text. The schematic surface (#050505) is the one exception — it's a purposeful "instrument view," not a body surface.
